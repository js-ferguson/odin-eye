# Introduction

The OdinEye API is a set of HTTP endpoints that provide support for integrations with a Valheim game server. For example, the API can be used to query the current online players, track boss progression, understand the current in-game day and day cycle, or read a player's submitted character stats.
The API is organized around REST: it accepts and returns JSON-encoded requests/responses and uses standard HTTP verbs. Each endpoint is documented individually below, categorized by the resource it primarily affects.

## Base URL

All URLs referenced in this documentation have the following base:

```
http://localhost:2469
```

This is the default -- change it to match wherever your server's `HttpServerAddress` is actually configured (see [Installation](../getting-started/installation.mdx)). There is no version segment in the URL (e.g. no `/v1/...` prefix) -- every path below is relative to the base URL directly.

## Authentication

:::note
Authentication has not been implemented at this time.
:::

There is no API key or any other authentication on any OdinEye endpoint. Anyone who can reach the configured `HttpServerAddress` can read (and, for the few `POST` endpoints, write) everything documented here -- see the "Server Address" remarks in [Installation](../getting-started/installation.mdx) for how to avoid exposing that to more than you intend.

## JSON casing

Every JSON body -- requests and responses alike -- uses **PascalCase** field names, matching the underlying C# model's own property names exactly (e.g. `MaxNumberOfPlayers`, not `maxNumberOfPlayers`). This is case-sensitive: a request body sent in camelCase will silently fail to populate the fields it was meant to.

## Requests

Making an API request involves combining a standard HTTP verb (`GET`, `POST`) with the URL to the resource, and for `POST` endpoints, a JSON body.

```curl showLineNumbers
curl -L -X GET 'http://localhost:2469/players' \
-H 'Accept: application/json'
```

## Responses

### Successful requests

| Status code | Description |
|---|---|
| `200 OK` | The request succeeded. Every successful response here uses this code -- there is no `201`/`204`. |

### Failed requests

| Status code | Description |
|---|---|
| `400 Bad Request` | The request was malformed, or failed validation (an invalid ID, a value out of range, an unrecognized `Type`, ...). See each endpoint's own description for its specific checks. |
| `404 Not Found` | The referenced player/character isn't currently connected. |
| `429 Too Many Requests` | Only on `POST /players/{id}/events` -- that player has already reported the maximum number of events allowed within the current window. |
| `500 Internal Server Error` | An unhandled exception. |

Error responses are **plain text**, not a JSON body (there is no [Problem Details](https://datatracker.ietf.org/doc/html/rfc9457)-style structure here) -- the status code itself is what a consumer should branch on.

## Versioning

There is no version number in the URL, and no formal versioning scheme yet -- this remains a small hobby project (see the note on the [Introduction](../intro.md) page). Breaking changes can happen without a version bump; if you're building something that depends on this API, pin to a specific [release](https://github.com/js-ferguson/odin-eye/releases) rather than always tracking the latest.
